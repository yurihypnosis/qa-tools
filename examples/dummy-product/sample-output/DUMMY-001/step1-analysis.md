## 1. 要件定義から理解したこと
### ビジネス目的
- タスク名が極端に長いとタスク一覧画面のレイアウトが崩れるため、タスク名に上限を設けて防ぐ。

### 主要機能と範囲
- タスク編集ダイアログのタスク名を 1〜100 文字に制限する。
- 101 文字以上で「保存」すると、入力欄の下にエラーを表示し、保存しない。
- 入力中、入力欄の右下に文字数カウンター「n / 100」を表示し、100 文字を超えたら赤字にする。
- 前後の空白は保存時に取り除き、取り除いた後の文字数で判定する（空白だけなら「タスク名を入力してください」）。
- 既存の 101 文字以上のタスクは、そのまま表示する。編集して保存するときにだけ上限を適用する。

### 制約条件
- API 側の文字数チェック（別 PBI）とタスクの説明欄は対象外。
- 絵文字・結合文字は、見た目の 1 文字を 1 文字と数える。[QA判断]

## 4. 統合的な理解と絞り込み戦略
### この機能の本質（1文）
タスク名を 1〜100 文字（前後空白を除く）に制限し、入力中のカウンターと保存時のエラーで利用者に上限を伝える。

### 最も重要なテスト観点（3-5項目）
1. 境界値：100 文字は保存でき、101 文字は保存できない（0・1 文字も含む）

3. 文字数カウンターの表示と、100 文字超過での赤字化
4. 既存の 101 文字以上タスクの表示と、編集して保存するときの上限適用
