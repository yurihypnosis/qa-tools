# ゲート規約（ゲート1・ゲート2）

## 契約

| 項目 | 内容 |
| --- | --- |
| 対象 | フルフローのゲート1（Step 1 → 2）とゲート2（Step 2 → 3） |
| 役割 | 止める・状態を見せる・次の操作を示す。成果物の中身の評価はしない |
| 再開条件 | QA のはっきりした指示だけ。⚠️ が残っていても、QA が指示すれば進む |

ゲートがある理由：AI は網羅の抜けや読み違いを自分では見つけにくく、後の工程ほど手戻りが大きい。ゲート1 は品質（分析の誤りを観点の前に止める）、ゲート2 はトークンの節約（観点が固まる前にケースを大量に作らない）のためにある。

## 止まる前の自己チェック（ゲート2 だけ）

1. `python3 <skill>/scripts/check_viewpoints.py output/{ID}/step2-viewpoints.md --json` を **1 つのコマンドで** 実行する（grep を何回も分けると、そのたびに許可の確認が出て QA の手が止まる）。
2. `findings` に `BOLD` か `HEADING` があれば、その箇所だけを差分 Edit で直す。
3. 同じコマンドをもう 1 回だけ実行する。自己修正は 1 回まで。まだ指摘が残れば、直さずにゲートへ進む。
4. 直した内容はチャットで報告しない（ゲートの表示項目を増やさないため）。

**直してよい基準**：「人が読んでも気づけない」かつ「情報を足さずに直せる」ものだけ。省略の印、空のセル、データ行の無い表、TP の欠番、`[要確認]`、決着していない食い違いは残す。情報を足す修正は「もっともらしいが間違った」内容を生み、誰も気づけない。迷ったら直さない。

## ゲート1 で表示するもの（この 5 点だけ）

```
## ⛔ ゲート1：テスト分析レビュー（停止中）

成果物: <output/{ID}/step1-analysis.md>

| チェック | 結果 |
| --- | --- |
| 衝突アラートのセクション | ✅ あり / ⚠️ なし |
| 未決着の衝突 | ✅ 0 件 / ⚠️ N 件 |
| [要確認] | 📋 N 件 |

次にやること:
1. 衝突アラートの各行について、採用する情報を決めてください
2. [要確認] に回答できるものは回答してください
3. 分析内容に修正があれば指示してください

次へ進むには「Step 2 の出力をしてください」と入力してください。
```

- 衝突が 1 件も無いときは、衝突アラートのセクションが無いのが正しい。その場合は「✅ 衝突なし」と表示する。
- パスに空白や日本語が入るので、リンクは `<>` で囲む。

## ゲート2 で表示するもの（この 3 点だけ）

```
## ⛔ ゲート2：観点レビュー（停止中）

レビューをお願いします: <output/{ID}/step2-viewpoints.md>
別の場所でレビューした場合は、確定版をこのパスに上書きしてから合図してください。

次へ進むには「Step 3 の出力をしてください」と入力してください。
```

ゲート2 ではチェックの結果、要約、感想を出さない。観点は必ずエンジニアと QA が中身を読んでレビューするので、要約はその代わりにならず、読む量を増やすだけである。

## 共通のルール

- 決められた項目のほかは表示しない（「補足」「所感」などを足さない）。
- ゲートで止まっている間は、次の Step の reference を読まない・下書きを作らない。
- `[要確認]` を推測で埋めない。消せるのは、QA の回答で確定値に置き換えたときか、`[QA判断: 対象外]`（理由必須）にしたときだけ。
- 修正の指示を受けたら、差分 Edit で直し、同じゲートの表示をもう一度出して止まる。番号の振り直しが必要なら、最後に 1 回だけ行う。
- ファイルの書き込みにシェルのリダイレクト（`>`、`cat <<EOF`）を使わない。ファイル全体が会話に再表示され、コンテキストを二重に消費する。
