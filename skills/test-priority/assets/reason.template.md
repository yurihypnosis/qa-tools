# 理由文の手本

`explain` で書く理由文の形。1 ケースの理由は 4 行（改行は JSON では `\n`）。

## 良い例（R2・smoke のケース）

```
R2・smoke で毎回確認する。
何を確認する？：タスク名が 100 文字ちょうどのとき、保存できること。
壊れると何が困る？：上限ちょうどの名前が保存できず、利用者がタスクを作れなくなる。
だからこの重要度：データの正しさに関わり、作業が止まるため、開始点の R3 から 1 段上げた。
```

## 良い例（判定不可）

```
決められない。
領域 DMY-XXX が .qa/test-priority.toml に無いため、開始点が引けない。
重要度を決めてほしい。決めたら output/test-priority/adjudications.json に書く。
```

## 悪い例と直し方

| 悪い例 | 何が悪いか | 直し方 |
| --- | --- | --- |
| `data 軸のため上げた` | 内部の記号で、読む人に通じない | 「データの正しさに関わるため上げた」 |
| `重要なので R1` | 理由になっていない | 何が壊れ、誰が何に困るかを書く |
| `適切に判定した` | 中身が無い | 「何を確認する？」から書く |
